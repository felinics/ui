## 实时状态面板：静默自刷新、单一状态与真实首帧门控

展示实时运行态的界面（如容器资源占用、远程桌面画面、会话活动流）遵守以下规则（提炼自 `bot-container.vue` 与 `bot-desktop.vue`）：

1. **可见时静默自刷新，不把刷新责任甩给用户**：
   - 状态与预览界面通过实时流或可见性守卫轮询（监听 `document.visibilityState`，隐藏时暂停、切回时立即拉取、组件卸载时清除定时器）自己保持最新，静默更新时不闪加载态、不弹 Toast，遇到瞬时网络抖动保留上一次有效数据。
   - **不要在实时面板上常驻一个手动“刷新（Refresh）”按钮**：常驻刷新按钮等于承认页面自己不会保鲜，还会引出各页按钮带不带图标、用不用 `sm` 的不一致。手动刷新仅限极少数开销巨大、必须由用户明确决定才触发的重型重算。
2. **更新时间用相对时间，不用跳动的绝对时间戳**：
   - 显示“刚刚更新 / 5 分钟前更新”（复用 `utils/date-time.ts` 的多语言相对时间格式化），只回答用户关心的“数据新不新”；严禁显示每秒跳动的 `2026/06/16 20:04:11` 日志式时间戳。
3. **同一个状态或进度在全屏只渲染一处**：
   - 严禁在画面中央放一张“准备中”进度卡，同时又在底部画一条重复的进度条。两个位置展示同一状态必然产生视觉噪音与状态不同步。
4. **遮盖黑色媒体/视频画面的封面必须完全不透明（`bg-background`）**：
   - 视频或远程桌面底框通常是纯黑的，如果上方的“正在准备”遮罩写成了半透明 `bg-background/95`，圆角边缘会透出底下的黑边显得脏乱。用来遮挡未就绪画面的封面一律用实色 `bg-background`。
5. **把后端布尔标志提炼为单一人类状态，不在画面旁摆满状态点矩阵**：
   - 不要把后端返回的 `enabled / running / desktop / browser / toolkit` 五六个布尔值原样画成一排圆点矩阵摆在实时画面旁边；实时视图本身已经能看出正在连接、安装中、正常或无法访问，正常时保持安静，仅在需要用户介入处理时展示一条明确的问题提示。
6. **穷举全部中间态，并以“真实首帧到达”而非“传输层连通”作为就绪门控**：
   - 实时媒体面不止有“加载中”和“运行中”两个状态，动笔前必须列出全部中间态：**未启动（idle）· 正在连接（connecting）· 已连接但首帧未到达 · 断线重连中（reconnecting）· 无法访问（can't-reach）**。每个中间态都在画面正中央给出可见的旋转图标与单行说明（不要塞在容易被 4:3 高画面顶出视口的底栏角落）。
   - **WebRTC / 视频流必须等真实画面帧渲染（`<video @playing>` 置位 `videoReady`，销毁时重置）才切掉加载遮罩**：传输层 `connected` 标志往往在第一帧画面解码前就变绿，直接绑 `connected` 会让用户面对一块像死机一样的纯黑框。

## 运行时真实状态与缓存对账

- 当页面采用“数据库记录优先”展示资源状态（如容器实例信息），但向底层运行时发起的实时查询返回**明确的 404（资源已彻底不存在）**时，必须将该状态对账收敛为“缺失（missing）”，引导界面进入“创建 / 重建”流程。
- 严禁吞掉明确的 404 错误继续把已消失的容器渲染为“健康运行中”，导致用户点任何操作（看指标、建快照、启停）都弹出自相矛盾的“未找到资源”报错。瞬时网络超时则容忍并保留上次记录；二级弹窗内的辅助拉取静默加载，不向主页面抛顶层错误。

## 危险操作与生命周期操作归位

1. **停止、重建、删除等重量级操作绝不放进页面标题栏（`PageShell #actions`）**：
   - 页面右上角 `#actions` 会被认知为整页的主推进动作（如“保存”或列表页的“新建”）；把 `Stop`、`Recreate`、`Delete` 放在标题栏会严重失衡，把低频运维动作塞进首屏扫视区。
   - **沉底归入专属操作区**：把启停、重建、删除等操作统一收进页面底部的独立分组卡片中。若卡片内同时包含常规运维动作（启动/停止）与危险动作（删除），分组标题命名为中性的 **“操作（Actions）”**，而不叫“危险区域（Danger zone）”；仅含纯破坏性操作时才命名危险区域。
2. **操作行不写复读动词的空洞警告词**：
   - 在底部操作行里，左侧直接写动作名，右侧放按钮（危险操作用实心红 `<Button variant="destructive">`）。不要在行描述里写“暂停或恢复运行时”这种复述标题的废话，也不要在行上堆砌“此操作不可撤销，请谨慎操作”的套话——真正的风险说明和“是否保留数据”的选项放在点击后弹出的确认框（行内用 `ConfirmPopover`，重型删除用 `ConfirmDeleteDialog`）里，在用户真正做决定的那一刻呈现。

## 无限增长列表必须虚拟化

会话列表、最近记录、模型选择器、带搜索的长下拉框等条目数可能随使用无限增长的列表，一律复用仓库现成的虚拟滚动实现，严禁对无上限数组直接裸写 `v-for`。

## AI 默认审美陷阱清单（严禁带入本系统）

未受约束的模型在写前端时会本能地抓起以下“AI 模板套路”，每一条都直接破坏本系统的平静白卡语言，一律禁止：

| 模型本能抓起的套路 | 为什么破坏本系统 | 本系统的正确做法 |
|---|---|---|
| 每个标题上方或卡片内先摆一个带底框的圆角图标 | 卡套卡 + 图标滥用 | 标题就是纯文字，不加装饰图标 |
| 蓝紫渐变背景、霓虹发光描边、渐变色大字 | 系统 90% 是黑白灰，无渐变、无发光 | 纯色语义 Token + 炭黑主按钮 |
| 等宽等高、每张带“图标+标题+描述”的三列特性卡片墙 | 营销落地页套路，常伴随卡套卡 | 顶部独立统计磁贴（`MetricReadout`）或 `SettingsSection` 行列表 |
| 毛玻璃（`backdrop-blur`）、彩色半透明玻璃卡、到处加 `shadow-md` | 本系统默认全平，阴影仅限 4 个浮层 Token | 实色 `bg-card` + 单根 1px `border-border` 细边，无阴影 |
| 所有文字和块全部水平居中 | 营销页习惯，破坏阅读对齐线 | 在 `max-w-3xl` 外壳内统一左对齐 |
| 把每个按钮都设成实心主按钮 | 摧毁视觉主次层级 | 每屏最多一个炭黑主按钮，其余用 `outline` 或 `ghost` |
| 在块左侧画一条 4px 彩色粗竖线做强调 | 破坏统一的单根 1px 细线语言 | 统一用 `CalloutBanner` 或单根细边，靠文字/图标色表达语义 |
| 弹性过冲（bounce）缓动、页面初次打开时的阶梯依次浮现动画 | 动效过度炫技、拖慢首屏响应 | 首屏直出无入场动画，交互使用固定时长档位与 `ease-out` |
| 到处用等宽字体（`font-mono`）装“技术感” | 破坏排版层级 | 普通文本一律用 `--font-sans` 与 `--text-*` 阶梯，仅真实代码/ID/终端用等宽 |
| 动不动就新开一个模态弹窗装普通设置 | 懒惰容器 | 首选页内 `SettingsRow` 或原地折叠；独立深层任务才用聚焦弹窗 |

## 脏模式 → 干净写法全局速查表

重构老页面（如对照经典反例 `bot-tool-approval.vue`）或提交自检时，按此表逐项清理：

| 脏写法（见到即删） | 正确写法 |
|---|---|
| `bg-muted/40`、`bg-background/70`、`bg-success/5` 烤死底色或手写透明度 | 继承 `bg-card`，需要软底色用 `--muted-soft` / `--destructive-soft` 等 Token |
| `border-border/50`、控件上写 `border-input` / `border-border` | 容器用 `border-border`；控件只用 `--field-edge-*` 或 `--border-hairline` |
| `text-[11px]`、`font-[550]`、`text-foreground/80` | 用 `--text-*` 字号阶梯、`normal/medium/semibold` 三档字重、零色度叠色梯 |
| `<Switch class="scale-90">` 用缩放改控件大小 | 用组件真实的 `size` prop，严禁 `scale-*` 缩放控件 |
| `focus-visible:ring-success/30` 彩色焦点环 | 键盘焦点只用中灰 `--ring`；输入框聚焦原位换 `--field-edge-solid` |
| `opacity-50 grayscale` 禁用态 | 全系统统一 `opacity-40` |
| 吸顶半透明模糊顶栏 `bg-background/95 backdrop-blur` | 标准 `<PageShell>` 标题栏 |
| 卡片内用满宽 `border-b` 或把 `border-b` 写在 `v-if` 包装 `div` 上 | 卡片内行用 `SettingsRow`，细线由列表提供、内缩由卡片提供，包装 `div` 不带边框 |
| 在 `SettingsSection` 白卡内给 `<Empty>` 加虚线框或灰底图标块 | 白卡内 `<Empty class="py-12">` 无边框无图标；独立列表外层 `<Empty>` 用实线 `border` |
| 在已带边框的卡片行内放自带 `border` 的 `ItemMedia variant="icon"` | 前导图标只用透明尺寸盒，卡片细线是唯一描边 |
| 把手动保存的 `SettingsSection #footer` 抄到根级设置页 | 根级设置页保存放 `PageShell #actions`；二级详情页才放 `#footer` |
| 用 `<Button variant="outline">` 充当 `Select` / `Combobox` 触发器 | 用 `SelectTrigger` 或 `selectTriggerClass`，避免宽下拉框按压抽动 |
| 弹窗底栏或主操作按钮用 `size="sm"` | 底栏与主操作一律用默认高度 `h-9` |
| 同一标题词在“页面标题 → 分组标题 → 行标签”连念三遍 | 单行分组直接省略 `SettingsSection` 的 `title` |
