## 页面外壳（PageShell）与间距阶梯

所有设置页与详情页都放置在居中的单列外壳中，绝不顶天立地贴满整个面板边缘（唯一例外是内容极少的 `about/index.vue` 采用偏上垂直居中）：

- **必须通过 `<PageShell>` 搭建带标题的页面**：`PageShell` 统一管理左侧 `pl-2` 内缩的页面标题（与下方卡片内文字的左边缘对齐）、右侧不内缩的 `#actions` 工具栏（与下方卡片的右边框外缘对齐）以及正文区（独立页面传 `variant="page"`，Bot 详情内嵌 Tab 传 `variant="tab"`）。严禁自己手写 `<header class="px-2">`，否则右上角的按钮会比下方满宽表格或卡片网格往里缩进 8px。
- **固定间距阶梯（直接复用，不自创边距）**：

  | 结构位置 | 标准间距 / 类名 | 说明 |
  |---|---|---|
  | 面板左右边缘 ↔ 内容列 | `px-6`（窄屏 `px-4 md:px-6`） | 外壳左右留白，内容绝不贴边 |
  | 面板顶部 ↔ 页面标题 | `pt-10`（Tab 内为 `pt-6`） | 标题上方留足呼吸空间 |
  | 内容底部 ↔ 面板底部 | `pb-12`（Tab 内为 `pb-8`） | 底部留白 |
  | 内容列最大宽度与居中 | `mx-auto max-w-3xl`（约 768px） | 宽屏下居中，行宽不被无限拉长 |
  | 页面标题 ↔ 第一个分组 | `mb-6`（个人资料页为 `mb-8`） | 由 `PageShell` 内部管理 |
  | 卡片分组 ↔ 卡片分组 | `space-y-8` | 区分不同业务区块的大间距 |
  | 分组小标题 ↔ 所属卡片 | `space-y-2.5` | 小标题为 `px-2 text-label font-medium text-muted-foreground` |
  | 卡片左右边缘 ↔ 卡片内容 | `--settings-inset`（16px） | 由 `SettingsSection` 卡片统一提供，卡片内任何块不再写 `mx-4` / `px-4` |
  | 卡片内行 ↔ 行 | `min-h-15 py-3 border-b border-border` | 由设置列表（卡片或 `SettingsList`）提供给其中的 `SettingsRow`，末行无细线 |
  | 行标题 ↔ 行描述 | `mt-0.5` | 由 `SettingsRow` 管理 |
  | 非列表类的卡片内边距块 | `py-4` 或 `py-5`，内部 `space-y-4` | 用于卡片内承载连续段落或表单块；左右留白已由卡片提供 |

## 单层卡片原则（严禁卡套卡与双描边）

动笔写标签前先在纸上或注释里画出页面的字符线框图（Wireframe），像审查空间复杂度一样砍掉多余层级：

1. **只给“一组行”套卡片，单件内容不套外卡**：`SettingsSection` 白卡是用来装多行 `SettingsRow` 的。如果内容本身是一排已经自带边框的统计磁贴（`MetricReadout`）或一张独立图表，直接放在分组小标题下方，绝不外面再套一层 `SettingsSection` 造成“大框套小框”。
2. **卡片内部绝不复用自带边框的图标底块（防双描边）**：在已经有 `border-border` 的卡片行内部放前导图标时，只保留透明的尺寸占位盒（`flex size-* items-center justify-center`），**严禁把自带 `border` 的 `ItemMedia variant="icon"` 或带框徽标塞进卡片行里做前导图标**——那会在同一个视觉单元上同时画出卡片边框和图标盒边框两道线，违背“单层细线”底线。
3. **默认不加装饰性图标**：卡片标题或空状态顶部不堆叠装饰图标；任何卡片级或大块大尺寸的新图标需经维护者确认。

## 分割线的两种宽度：卡片内缩 vs 容器满宽

分割线只有两种职责和两种宽度，放之前先回答“它是在分隔**同一个表面内部的条目**，还是在切分**容器自身的结构**”：

1. **卡片内部行与行之间 → 左右内缩（Inset）**
   - 细线绝不能碰到圆角卡片的左右外边框（否则会把一张连续的圆角白卡切成几块叠起来的砖头）。
   - 卡片以 `--settings-inset` 给全部内容统一留白，行间细线画在**行元素**上（由列表规则提供给 `SettingsRow`，最后一行自动去掉），因此天然落在内缩范围内。
   - **严禁把 `border-b` 写在包裹 `v-if` 的透明外层包装 `<div>` 上**：当那个包装 `<div>` 恰好成为卡片的最后一个子节点时，它的满宽 `border-b` 会直接压在卡片自身的底边框上，不仅切穿圆角，还会叠出一条粗黑双线。
2. **切分容器整体结构 → 边缘满宽（Full-bleed）**
   - 弹窗的顶栏/底栏分隔带、菜单内的分组分隔线（`DropdownMenuSeparator`，严禁加 `mx-1` 留白变悬空短线）、章节标题下划线或区块之间的独立 `<Separator>`，一律横跨容器左右边缘，由内容区自己保留内边距。

## 列表↔详情推拉切换与进出路径对称

- **同页列表与详情切换使用 `useViewSwap` + `<SwapTransition>` + `<DetailPane>`**（样板 `pages/web-search/index.vue`）：
  ```vue
  <SwapTransition :direction="direction">
    <ListView v-if="view === 'list'" @open="openDetail" />
    <DetailPane v-else :back-label="t('feature.title')" @back="backToList()" />
  </SwapTransition>
  ```
  调用 `openDetail()` 时列表向左滑出、详情从右滑入（`forward`），详情从顶部开始浏览；调用 `backToList()` 时反向推回（`back`），并自动恢复列表之前的精确滚动位置。首次进入页面时直接渲染，不播入场动画。
- **进出路径步数对称**：从哪里点进来，点一次返回就应该回到哪里。如果从聊天侧栏点一次打开某个管理页，点“返回”却要在设置里退两次才能回到聊天，说明路由或返回路径设计有缺陷，必须修正为一步直达来源视图。

## 窄屏重排、容器查询与字号缩放

页面必须同时经受住三种尺寸变化的考验：浏览器缩放（50%–200%）、可拖拽变窄的面板宽度、以及用户调大的系统/根字号：

1. **可变宽面板内部使用容器查询（`@container`），不用视口断点**：`sm:` / `md:` 监听的是整个浏览器窗口宽度；而 Dockview 分屏或主从双栏面板在窗口不变时自身宽度会大幅变化。凡是放在可变宽面板里的多列网格或工具栏，使用 `@container` 响应自身容器宽度；仅整页顶层 `max-w-3xl` 列使用视口断点（`grid-cols-1 sm:grid-cols-2`）。
2. **随文字缩放的图标用 `em`，固定控件内的图标用 `rem`（`size-*`）**：`size-4`（`1rem`）永远相对于根字号；当图标紧挨着大号标题（如提供商详情页 `text-lg` 名称旁的品牌 Logo）时，使用 `size-[1.5em]` 使其随旁边文字等比放大；固定高度按钮内的图标则保持 `size-4` / `size-3.5` / `size-3` 阶梯。
3. **不锁死仅适配单一语言的像素宽度，单行文本统一加 `min-w-0 truncate`**：在 `flex` 行内，给可能变长的名称、面包屑或返回按钮文字加 `min-w-0 truncate`，并给旁边的图标或按钮加 `shrink-0`，确保在窄屏 + 中文/日文最长文案下优雅省略，绝不撑破容器或把相邻按钮挤出屏幕。

## 滚动归属与滚动条预留槽（防横向抖动）

1. **明确唯一的滚动容器，禁止嵌套双滚动条**：桌面端外壳锁死了 `body` 滚动，每个独立页面或设置框架只由一个指定容器拥有 `overflow-y-auto`（设置子页复用 `settings-section` 的现有滚动区，不自己再套一层 `overflow-y-auto`）。
2. **横向位移过渡使用 `overflow-x-clip`，禁用 `overflow-x-hidden`**：列表↔详情推拉切换存在 `±24px` 横向位移；按 CSS 规范，一旦设置 `overflow-x: hidden`，浏览器会把 `overflow-y` 也强制提升为可滚动容器，从而抢走外层祖先的纵向滚动。裁剪横向溢出必须写 `overflow-x-clip`。
3. **承载居中列（`mx-auto max-w-*`）的页面级滚动容器必须加 `[scrollbar-gutter:stable]`**：居中列的左右边距由滚动容器的可用宽度算出；如果没预留滚动条槽位，从短 Tab 切到长 Tab（或展开折叠区触发滚动条出现）的瞬间，滚动条吃掉十几像素宽度，整页标题和卡片边缘会突然往左横跳一下。在拥有 `overflow-y-auto` 的外层滚动容器上统一声明 `[scrollbar-gutter:stable]`（如 `bots/detail.vue` 与 `settings-section/index.vue`），切勿写在内部页面内容上。

## 深色模式零裸色自检清单

UI 契约守卫脚本只扫描 `packages/ui` 的裸颜色，**`apps/web` 页面没有自动 lint 兜底**。深色模式不是最后补做的任务，而是“从第一行起就不写任何裸颜色”的自然结果：

- **提交前必跑的正则自检**：在修改过的页面目录运行正则搜索：
  `bg-white|bg-black|text-white|text-black|-gray-|-zinc-|-slate-|-neutral-|#[0-9a-fA-F]{3,6}|dark:|style=`
  除物理旋钮滑块（`Switch` / `Slider` 的白色圆柄）外，任何命中都应替换为语义 Token（`bg-card`、`bg-background`、`text-foreground`、`text-muted-foreground`、`border-border`）或零色度叠色梯（`--ui-hover`、`--ui-selected`、`--ui-pressed`、`bg-accent`）。
- **出现 `dark:` 前缀本身就是坏味道**：语义 Token 和中性叠色梯在深浅色下自动切换，不需要写 `dark:`；如果你发现自己在页面里写 `dark:bg-...`，说明底色用了浅色硬编码，回去把底色换成 Token。
- **Canvas 与图表（ECharts）动态解析颜色**：Canvas 无法直接读取 CSS 的 `oklch()` 变量，复用 `bot-overview.vue` / `usage/index.vue` 中的颜色解析逻辑，并在 `isDark` 变化时重新执行；图表线条只用黑白灰（`--foreground` / `--muted-foreground`），不用品牌紫。
